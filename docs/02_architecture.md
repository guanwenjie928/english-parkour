# 技术架构

## 整体架构

```
┌─────────────┐      ┌─────────────┐      ┌─────────────┐
│   学生端     │◄────►│  Node.js    │◄────►│   MySQL     │
│  (Phaser 3) │ WebSocket│ 游戏服务器  │  SQL  │  单词库/用户 │
│  平板浏览器  │      │  Socket.io  │      │  房间/报表   │
└─────────────┘      └─────────────┘      └─────────────┘
        ▲
        │ WebSocket
┌─────────────┐
│   老师大屏   │
│  (纯Web页面) │
│  实时数据面板 │
└─────────────┘
```

## 服务端模块

| 模块 | 技术 | 职责 |
|------|------|------|
| HTTP API | Express | 房间创建、加入、历史数据 |
| WebSocket | Socket.io | 实时游戏状态同步 |
| 游戏逻辑 | Node.js | 房间管理、计时器、判定 |
| 数据库 | MySQL | 持久化存储 |

## 客户端模块

| 模块 | 技术 | 职责 |
|------|------|------|
| 游戏引擎 | Phaser 3 | 跑酷渲染、物理、动画 |
| UI框架 | HTML/CSS | 虚拟键盘、面板、排行榜 |
| 网络层 | Socket.io-client | 实时通信 |
| 音频 | Web Audio API | 音效播放、音量控制 |

## 数据流

### 学生答题
```
学生输入答案 → 客户端本地校验格式 → 发送answer事件
→ 服务器校验正确性 → 广播result事件给全房间
→ 各客户端更新角色状态
```

### 位置同步
```
服务器50ms广播 → { players: [{id, track, progress, speed, status}] }
客户端插值渲染 → 平滑移动
```

### 道具释放
```
释放者发送item_use → 服务器校验合法性 → 广播item_effect
→ 目标客户端强制弹出拼写面板
```

## 性能指标

| 指标 | 目标 |
|------|------|
| 网络延迟 | < 100ms（同机房） |
| 位置同步频率 | 50ms |
| 同时在线房间 | 50个（轻量服务器） |
| 单房间人数 | 8人 + 1老师观战 |
